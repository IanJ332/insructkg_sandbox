# Research limitations

There are five artificial students, 21 original fixture attempts, later actual local PL Dev User attempts, three SQL questions and two small SQLite datasets. These demonstrate engineering behavior, not general SQL competence, multi-course coverage or student learning. Multiple successful technical runs do not increase sample size for a learner study.

The existing 469-judgment graph covers multiple lectures while the available PDF is one 17-page lecture. All original edges are unreviewed; manual mappings/provisional edges can introduce confounds. No fresh completed extraction, validated graph precision/recall or instructor review has been established. Fresh parsing timed out despite resolved import dependencies.

No live feedback inference has run. Mock contract tests and deterministic fallback cannot measure generative quality, hallucination rates, pedagogical effect or actual cost. Page lexical retrieval is simple and has no retrieval-relevance benchmark. Rule filters cannot guarantee no solution leakage or prompt injection.

Profiles use a transparent beta heuristic with question-to-concept attribution, not validated knowledge tracing. Out-of-order feedback excludes future persisted records, but batch preparation uses preexisting history rather than sequential uncommitted rows. Attempts differ in difficulty and concepts overlap. No causal inference about personalized improvement is supported.

The dashboard is loopback, unauthenticated and synthetic-only. CSV ingestion is explicit, not automatic production integration. Hosted PL network permissions, SSO/identity consent, concurrent course load, retention/export controls, async inference, backup automation and incident response are unverified. No IRB/institutional approvals or legal redistribution rights are asserted. The empirical learning study is future work.
