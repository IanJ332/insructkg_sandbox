Year 3 Task 1 adds a student profile with scores, attempt counts, recency and error tags; it proposes broader non-programming support, deployment in at least four engineering courses and a formal learning-impact evaluation. Those are project goals, not evidence that deployments or outcomes occurred. The proposal's Appendix A describes earlier PrairieLearn integration as partial and mainly for testing.

The October 21 transcript lines 88–114 emphasizes concept-level progress across assignments, manual question tags and reuse of the existing system; lines 12–16 describe snapshots, external grading and a separate student-information service. October 27 lines 48–54 reiterate snapshots, tagged assignments, semester history, a separate backend and feedback through external grading. These are consistent with Objective 1, while the proposal describes a broader eventual program. Transcript text is private and not reproduced here. Neither proposal language about scores nor a model's estimate proves student understanding: the current sparse heuristic is descriptive and must retain its observations, counts, recency, uncertainty and provenance. ## Storage decision

Retain **Option A**, SQLite and immutable local graph snapshots, for the bounded sandbox. Existing attempt persistence, prior-history reads, reviewed prerequisite traversal and version binding cover the operations currently being tested; the immediate blocker is quality of evidence-grounded feedback, not a demonstrated missing database query. Option B (thin adapter to the previous research backend) requires actual access and comparison. Option C (minimal new PostgreSQL or Neo4j components) requires a specific unmet operation, measurable benefit and migration/rollback evidence. This decision is a bounded functional substitute, not a claim of paper architecture or verified functional equivalence.
